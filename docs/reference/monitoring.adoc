== Local Monitoring

=== Overview

The monitoring commands initialize, start, inspect, and stop a local Grafana and Prometheus stack for development clusters.
Prometheus scrapes local metrics ports from 9612 through 9169 for Coherence clusters with metrics enabled.
For example, `cohctl start cluster my-cluster -t 9612` starts a local cluster with metrics enabled.

The generated stack requires Docker Compose V2 or newer.
By default, Grafana and Prometheus bind only to `127.0.0.1`.
Prometheus is not authenticated, and this stack is not intended for production use.

If you are running a Coherence version before 14.1.2-0-0 or 25.03, set the following property on each cluster member so it emits the metric names used by the current dashboards:

* `-Dcoherence.metrics.legacy.names=false`

The available commands are:

* <<init-monitoring,`cohctl init monitoring`>> — initialize local monitoring
* <<start-monitoring,`cohctl start monitoring`>> — start Grafana and Prometheus
* <<stop-monitoring,`cohctl stop monitoring`>> — stop Grafana and Prometheus
* <<get-monitoring,`cohctl get monitoring`>> — report the current monitoring status

[#init-monitoring]
==== Initialize Monitoring Stack

include::../../build/_output/docs-gen/init_monitoring.adoc[tag=text]

[source,bash]
----
cohctl init monitoring
----

Initialization downloads the dashboards and base configuration into a staging directory, validates them, and creates these authoritative local files under `~/.cohctl/monitoring`:

* `docker-compose.cohctl.yaml` — generated Compose model used by cohctl
* `monitoring.env` — persisted `COHCTL_MONITORING_BIND_ADDRESS`
* `grafana-admin-password` — generated Grafana administrator password

The monitoring configuration is downloaded from the `coherence-cli` Git tag that exactly matches the running cohctl release version.
cohctl does not download monitoring configuration from the moving `main` branch or fall back to it.
A development build without a valid semantic release version must be rebuilt with version metadata before it can initialize monitoring.
Grafana dashboard definitions continue to come from the Coherence Operator dashboard repository.

The password is generated from 32 random bytes, displayed once after successful initialization, and stored without a trailing newline.
On POSIX systems cohctl requires the file to be owned by the current user with no group or other access; on Windows it inherits the ACL of the user's cohctl configuration directory.
Routine start and status output never displays the password.

The generated Grafana container starts with a brief root bootstrap so it can read both native Linux owner-only files and Docker Desktop's mapped files.
All capabilities are dropped except `DAC_OVERRIDE`, `SETUID`, and `SETGID`, and `no-new-privileges` prevents later elevation.
After checking the secret, the entrypoint uses the image's `/bin/busybox su` to become the `grafana` account and uses `/bin/busybox id` to verify UID `472` and group `0` before invoking `/run.sh`.
Grafana's startup, plugins, and server run under that normal image identity, with no effective capabilities.
This also applies when cohctl itself is invoked as root.
Downloaded loader and shell startup environment hooks are rejected because they could execute before the identity drop.
Docker records the bootstrap user as root; use `docker compose exec --user 472:0 grafana ...` when troubleshooting under the server's identity.
The image must provide the BusyBox `su` applet, the `grafana` account with that identity, and writable data/plugin directories; the tracked image does so.
cohctl never changes the host secret's owner or broadens its permissions, and does not create another password file in the container.
If a remapped or remote daemon cannot read the mapped secret even during bootstrap, startup fails.
Native Windows ACL mapping, complete generated-stack startup through Desktop host-file sharing, and custom plugin installation still require runtime qualification.

The generated entrypoint reads the secret once, checks the read result and password format, then invokes Grafana's `/run.sh` with `exec`.
A missing, unreadable, empty, or invalid secret stops the container before Grafana starts.
The password is absent from Compose values, Docker-configured environment values, and process arguments.
It is exported inside the container as `GF_SECURITY_ADMIN_PASSWORD` for Grafana itself; Grafana's standard `__FILE` wrapper also exports secrets internally.

Generated bundles created before this bootstrap and entrypoint fix must be regenerated: save customizations, run `cohctl stop monitoring` to remove the old containers, then initialize again.
The new CLI rejects their older generated model for start and status; stop remains available.

Example abbreviated output:

[source,text]
----
This command will:
1. Create or replace /Users/timbo/.cohctl/monitoring
2. Download Grafana dashboards and monitoring configuration
3. Generate a protected Grafana administrator password
4. Pull Grafana and Prometheus images

Are you sure you want to initialize monitoring? (y/n) y
...
operation completed

Grafana administrator user: admin
Grafana administrator password: <generated-password-shown-once>
The password is stored in /Users/timbo/.cohctl/monitoring/grafana-admin-password and will not be displayed again.
Generated compose configuration: /Users/timbo/.cohctl/monitoring/docker-compose.cohctl.yaml
----

Re-running initialization generates a new password and replaces the complete monitoring directory only after all staging and image-pull work succeeds.
Initialization refuses to replace the directory while its monitoring containers are running; stop them first.

===== Select a bind address

An unset `COHCTL_MONITORING_BIND_ADDRESS` defaults to `127.0.0.1`.
To bind to a different IPv4 or IPv6 address, set it only when initializing:

[source,bash]
----
COHCTL_MONITORING_BIND_ADDRESS=192.0.2.15 cohctl init monitoring
----

cohctl persists the validated address in `monitoring.env`; later inherited environment values cannot silently override it.
Hostnames, CIDR notation, values containing ports, empty values, and malformed addresses are rejected.
Specific non-loopback addresses produce an exposure warning.
Explicit wildcard values `0.0.0.0` and `::` are supported but produce a stronger warning because both services become reachable on every matching interface and Prometheus has no authentication.

===== Existing legacy installations

An installation with a usable `docker-compose.yaml` remains in legacy mode only when all three generated-bundle paths are absent.
cohctl inspects it, warns about known or missing Grafana credentials and exposed ports, and does not rewrite it implicitly.
Re-run `cohctl init monitoring` to rotate to a generated password and loopback binding.
A partial or corrupt generated bundle is treated as an error by `start` and `get`; cohctl never silently falls back to a legacy credential in that state.
An existing directory, special file, or valid or dangling symlink at any generated-bundle path is also invalid, even when the other two paths are absent.
The error identifies the offending path and directs you to reinitialize; `cohctl stop monitoring` retains the recovery rules described below.

[#start-monitoring]
==== Start Monitoring Stack

include::../../build/_output/docs-gen/start_monitoring.adoc[tag=text]

[source,bash]
----
cohctl start monitoring
----

cohctl validates the complete security bundle and starts the authoritative generated Compose model:

[source,text]
----
Issuing docker compose --env-file /Users/timbo/.cohctl/monitoring/monitoring.env -f /Users/timbo/.cohctl/monitoring/docker-compose.cohctl.yaml up -d
...
Open the Grafana dashboard at http://127.0.0.1:3000/d/coh-main/coherence-dashboard-main using administrator user admin.
Read the password from /Users/timbo/.cohctl/monitoring/grafana-admin-password.
----

The standalone `docker-compose` command can be selected with `-D`, but it must report a V2 or newer version for a generated installation.

To operate the generated project manually, always pass both authoritative files:

[source,bash]
----
cd ~/.cohctl/monitoring
docker compose --env-file monitoring.env -f docker-compose.cohctl.yaml up -d
----

Wait for Grafana to become ready before signing in with administrator user `admin` and the generated password.

[#stop-monitoring]
==== Stop Monitoring Stack

include::../../build/_output/docs-gen/stop_monitoring.adoc[tag=text]

[source,bash]
----
cohctl stop monitoring
----

Stopping does not require reading or validating the Grafana password.
This ensures an exposed stack can still be stopped if the password file is missing or has incorrect permissions.
cohctl prefers a parseable generated Compose file, then a parseable legacy file, and reports both paths when neither is usable.

[source,text]
----
Are you sure you want to stop monitoring? (y/n) y
Issuing docker compose --env-file /Users/timbo/.cohctl/monitoring/monitoring.env -f /Users/timbo/.cohctl/monitoring/docker-compose.cohctl.yaml down
...
----

[#get-monitoring]
==== Get Monitoring Stack Status

include::../../build/_output/docs-gen/get_monitoring.adoc[tag=text]

[source,bash]
----
cohctl get monitoring
----

Example abbreviated output for the default loopback binding:

[source,text]
----
Monitoring status
Grafana:    http://127.0.0.1:3000/d/coh-main/coherence-dashboard-main
  Image:    grafana/grafana:11.6.2
  Status:   ok, version=11.6.2
Prometheus: http://127.0.0.1:9090/
  Image:    prom/prometheus:v2.53.4
  Status:   Prometheus Server is Healthy.
Compose:    /Users/timbo/.cohctl/monitoring/docker-compose.cohctl.yaml
----

For an IPv6 binding, cohctl brackets the address when constructing URLs, for example `http://[::1]:3000/`.
